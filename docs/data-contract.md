# 正式資料串接介面

已加入 TWSE 全市場日報 adapter、Cloudflare KV 分組快取與每日排程。一般本機啟動保留示範資料；Cloudflare 正式模式使用全部上市公司名錄與真實資料，部署步驟見 [cloudflare.md](cloudflare.md)。

`src/provider.js` 依建置模式選擇來源：示範模式以 `loadDataset()` 取得 `src/data.js` 的 `demoProvider.load()`；API 模式以 `loadMarketSummary()` 讀取名錄與市場摘要。兩者共用下列資料格式：

```js
{
  info: {
    mode: 'demo', // 正式資料使用 'twse'
    label: '示範資料',
    asOf: '2026-10-16', // 最近已取得行情及法人市場報表的交易日
    note: '資料來源、更新時間及限制'
  },
  dates: ['2026-10-15', '2026-10-16'], // 實際市場報表交易日，舊到新；個股仍可能缺漏
  stocks: [{
    symbol: '2330', // 代碼以字串保存，亦支援六碼存託憑證
    name: '台積電',
    sector: '半導體',
    market: '上市',
    history: [{
      date: '2026-10-16',
      open: 1000,
      high: 1020,
      low: 990,
      close: 1010, // OHLC 單位皆為新台幣
      volume: 10000000, // 單位：股，非張
      institutions: [
        { name: '外資', buy: 2000000, sell: 1000000 },
        { name: '投信', buy: 500000, sell: 300000 },
        { name: '自營商', buy: 200000, sell: 400000 }
      ] // buy、sell 均為股數
    }]
  }]
}
```

範例金額僅說明格式，不是正式行情。股數在畫面除以 1,000 換算成張；法人買賣超使用未經四捨五入的股數加總。畫面成交張數取整數。

## 計算約定

- 歷史資料必須依日期由舊到新排列，不能有同一股票重複日期。
- `asOf` 取同一天的市場行情與法人報表日期，不以日曆推定；休市、未發布、HTTP 錯誤分別處理。新上市、停牌與來源缺列不再要求全體股票具有相同歷史，避免整個市場日期被一檔股票卡住。
- 全部公司均保留在名錄；沒有當日 OHLC 的公司不列入當日排行，不能用過期價格冒充當日行情。新增公司可有空歷史，資料不足顯示資料不足。法人缺列不補零；缺少市場交易日也會中斷法人累計與連續日數。
- 產業法人合計使用所選當日／5 日／20 日區間內資料完整的個股；同一區間的金額、張數、三家法人分項與有效家數使用相同個股集合，缺少任一天的價格或法人資料即排除該股整段區間。只要仍有可用個股即顯示部分加總，畫面不另顯示缺漏提示；無任何可用個股時數值、排行名次與 TOP1 留白，不顯示數值長條。真實零值則保留為零並正常參與排名。個股明細仍保留供查看，缺少的法人數值留白，不補零。
- 自選法人數據以金額為主、張數為輔；產業排行只顯示金額（欄位標題標示單位「億」，手機無標題時金額仍帶「億」），產業明細以占量為輔；逐檔逐日將法人淨買賣股數乘以當日收盤價，再累計所選當日／5 日／20 日區間，最後除以 100,000,000，以億元顯示兩位小數。缺少任一天的價格或完整法人資料即排除該個股整段區間，無可用個股時數值留白。這是收盤價換算，並非實際成交金額；不可用產業總張數乘單一股票價格，亦不可用最後一天價格換算整段區間。買超／賣超排行、TOP1 與產業明細排序皆依未四捨五入的金額判定。產業分項仍使用三類法人資料皆完整的同一個股集合；單一自選個股的法人分項可在其他類別缺漏時獨立顯示。
- `getSnapshot()` 先截斷到選定資料日，再計算所有指標，避免讀取未來資料。
- 產業明細最上方的「法人累計淨買賣超」走勢圖來自 `/api/v1/sectors/{name}` 的 `flow`：近 20 個交易日，逐日把三大法人各自與合計的淨買賣股數 × 當日收盤價累加。只計 20 日資料完整的個股，最後一點因此等於同一明細的 20 日金額；任一天缺資料的個股整段排除，不補零，沒有完整個股或交易日不足 20 天時為 `null`，畫面改顯示資料不足。外資、投信、自營商最近一段連續買賣只在與平均股價背離時才標在圖上：賣超期間產業平均股價上漲，或買超期間下跌，且該段期間內股價變動幅度至少 0.5%（`DIVERGENCE_MIN_PERCENT`）。符合的那一段以較粗的淡色描出，開始那天在線上畫空心圓並標徽章「10/14 轉賣」（前一日淨額為零時為「起賣超」），同一家法人金額下方也只在這時才顯示「轉賣」「連賣 8 日」徽章（隨所選日期，以到那天為止的一段判斷），轉賣標在點下方、轉買標在點上方，相近的標籤上下錯開；方向一致的、沒有股價資料的，以及連續到窗口起點而沒有轉折日的，圖上不標；依 `flow.daily` 從最新一日往前數同方向的交易日，連續天數顯示在上方各法人金額下一行（如「連賣 8 日」），並隨所選日期換成到那一天為止的連續買賣；最新一日淨額為零時不標示，連續到資料起點的一段沒有轉折，只描出線段。同期平均股價來自 `price`：以 20 日前一個交易日收盤為基準，產業內 21 個收盤價都齊全的個股取等權平均累計漲跌，未還原權息。它以淺灰色區域畫在同一張走勢圖的背景，另用自己的比例尺且不標刻度，只用來比較方向與轉折，高低不與金額對應；當日數值顯示在日期列右側。圖上可點選、拖曳或用方向鍵查看各日累計；明細不再列出當日／5 日／20 日的數字表，API 的 `periods` 仍照舊回傳。
- 產業「買超 X／Y 檔」跟隨當日／5 日／20 日區間：X 為該區間淨買賣超金額嚴格大於零的個股數，Y 為產業內的個股總檔數；資料不足的個股不計入 X 但仍計入 Y，零值屬有效資料但不列買超，整個產業都沒有有效資料時留白，不顯示「0／Y」。金額加總仍只使用資料完整的個股集合。
- 產業明細的法人淨買賣超摘要以當日／5 日／20 日並列，金額下方顯示區間占量＝合計或各法人淨買賣超股數／同一批完整個股在區間內的成交股數合計 × 100%，保留正負號。分子與分母使用同一個股集合；該集合任一檔在區間內任一日缺少成交量時整格留白，不以部分成交量計算。
- 產業個股在當日、5 日、20 日金額旁顯示占量百分比（取代張數）＝該區間三大法人淨買賣超股數／同一批交易日的成交股數 × 100%，保留正負號；當日即個股法人占量。區間內任一日成交量缺漏、成交量非正數或三大法人資料不完整時留白，不以零替代。每檔個股在當日、5 日、20 日各畫一條水平長條，長度為該金額絕對值占該股三個區間中最大值的比例（各股獨立比例尺，用於比較同一檔的區間大小，不可跨個股比較柱長），紅為買超、綠為賣超，金額缺漏時只留空軌道。這些資訊使用已下載資料計算，不增加 API 請求。
- 產業分類使用 `data/custom-sectors/` 的自訂分類（16 個大類、92 個細產業），由 `scripts/build-custom-sectors.mjs` 產生 `shared/custom-sector-data.js`。KV 內的已發布名錄仍保留證交所官方產業別，`MarketService.market()` 讀取時才套用：`sector` 為細產業、`sectorGroup` 為大類、`twseSector` 為官方產業別；ETF 不套用，`sector` 維持 `ETF`。分類表沒有的新上市公司依官方產業別歸入預設細產業，官方產業別也不認得時歸入「其他」，不會中斷資料。分類只有一份，切換歷史日期時也使用目前的分類。`/api/v1/sectors/{name}` 與 `/api/v1/stocks?sector=` 接受細產業或官方產業別名稱。除市場清單的產業篩選可選大類外，法人排行、產業明細、個股標籤與情緒卡片都只使用細產業。流入、流出與排行只代表三大法人的估算金額，不是全市場資金。
- 首頁情緒卡片的「大戶異常」來自 `sentiment.market.unusual`：逐檔以三大法人淨買賣股數 × 收盤價計算每日金額，取最新交易日之前 20 個交易日的每日金額絕對值平均作為「平常」，最新一日金額達平常的 2 倍以上（`UNUSUAL_MULTIPLE`）即為異常；買超、賣超各取金額最大的一檔，回傳 `{ symbol, name, amount, average, multiple }`，該方向沒有異常時為 `null`。只計上市普通股，21 個交易日中任一天缺少收盤價或完整法人資料即不列入，不以較短期間替代。金額為估算值。`quietBuying` 為同一規則下的買超異常個股中，當日漲跌幅小於或等於 0（收平或下跌）者，依買超金額取前 3 檔，回傳 `{ symbol, name, amount, average, multiple, changePercent }`，沒有符合時為空陣列；首頁以「買超未漲」列出。
- 市場情緒分數可在設定選擇半圓儀表（預設）或橫向刻度，存於瀏覽器偏好的 `moodStyle`，只影響顯示。卡片的市場數字來自 `sentiment.market`，以最新交易日的上市普通股計算（不含 ETF、上櫃），與情緒分數同一母體：上漲／平盤／下跌家數依當日漲跌幅；`institutionalNet` 為最新一日的法人淨買賣金額＝逐檔三大法人淨買賣股數 × 當日收盤價加總，屬估算值；`institutionalStreak` 為同方向連續交易日數，正數連買、負數連賣，每日都以同一金額判斷方向，遇到淨額為零或資料不足的交易日即中斷，最多只能回溯到已載入的歷史；`inflow`／`outflow` 為最新一日依產業加總同一金額後，淨買超與淨賣超最多的產業（`{ sector, amount }`，零值不列，該方向沒有產業時為 `null`）。流入、流出只代表三大法人，不是全市場資金。有效樣本未達 80% 時，家數與該日金額回傳 `null`，畫面顯示「—」，不以部分加總呈現。
- 個股視窗走勢圖下方的三大法人交易量線：`priceHistory` 每日另含 `foreignVolume`／`trustVolume`／`dealerVolume`（該法人當日買進＋賣出股數，不分方向）與 `institutionalNet`（三大法人當日淨買賣股數）；缺列、重複或非有效數值回傳 `null`，不以零替代。一條線依三家交易量比例分三色，寬度對齊走勢圖；標題同列右側的淨買賣金額＝三大法人淨買賣股數 × 當日收盤價，為收盤價換算的估算值，一億以上以億元顯示兩位小數，未滿一億以萬元顯示，紅色為淨買、綠色為淨賣。任一法人或收盤價缺漏時金額顯示「—」；任一法人缺漏時線條不分色。預設顯示區間最後一日，選取其他交易日時跟著該日變動。
- MA5、MA20、MA60 分別取最近 5、20、60 個交易日的收盤價平均，包含當日。資料不足時回傳 `null`。
- 預設 KD (9,3,3)，第一個完整 9 日窗口才開始遞推。前值 K、D 為 50；全平盤窗口 RSV 採 50。修改平滑係數時使用 `(n - 1) / n` 與 `1 / n`。
- 保留足夠的歷史暖機期。相同 KD 參數若暖機起點不同，初期值可能不同；應與資料供應商確認算法。
- 示範資料未做除權息／分割還原。正式資料需決定並一致使用還原或未還原價格，並標示口徑。
- 法人資料需確認外資包含範圍，以及自營商自行買賣／避險的合併規則。買進、賣出與買賣超需使用同一資料口徑。

## 法人累計與連續買賣日數

`getInstitutionalSummary()` 接收已截斷至所選資料日的歷史資料；`getSnapshot()` 將結果放在 `institutionalSummary`。`total.net5/net20` 為三大法人合計，`institutions[名稱].net5/net20` 為各法人的累計，皆以股為單位，畫面最後才換算為張。計算窗口包含所選資料日，以最近 5／20 筆交易日資料為準，不插入週末或休市日。

各窗口必須有完整日數與有效買賣資料；不足日數、缺少該法人、重複分類或非有限／負數買賣量均回傳 `null`，畫面留白，不以零補足。合計需要當日三類法人資料均有效；單一法人仍可在其他類別缺漏時獨立累計。

外資、投信連續日數由資料日往前計算每日淨買超或淨賣超，遇到反向或淨額為零即中斷。資料日淨額為零顯示「當日持平」，缺漏則留白。若連續日數回溯至資料起點或缺漏，使用「至少連買／連賣 N 日」標示可確認的下限，不跳過缺漏資料。連續日數與累計淨額各自計算，累計正負不代表當日連續方向。

## KD 技術建議規則

`getTechnicalSignal()` 接收已截斷至資料日、已計算 KD 與均線的歷史資料，僅比較最後兩個交易日。`getSnapshot()` 回傳的 `signal` 含 `code`、`tone`、`label` 與 `reason`，上方自選總覽與下方市場清單共用同一結果；切換日期或 KD 設定會重新計算。

按以下順序判讀，第一個符合的條件即為該日結果：

1. 缺少連續兩日的有效 K、D（有限值且介於 0–100）→ 資料不足。
2. 低檔黃金交叉且收盤價 ≥ MA20、當日 MA20 ≥ 前日 MA20 → 留意買點；趨勢未確認或均線不足 → 反彈觀察。
3. 高檔死亡交叉 → 留意賣點。
4. 其他死亡／黃金交叉 → 動能轉弱／動能轉強。
5. K < 20／K > 80 → 低檔觀察／高檔觀察，不因極端讀數直接產生買賣提示。
6. K > D 且符合前述 MA20 趨勢 → 偏多觀察；K < D → 偏弱觀察；其他 → 中性觀望。

黃金交叉要求前日 K ≤ D、當日 K > D 且 K 上升；死亡交叉要求前日 K ≥ D、當日 K < D 且 K 下降。低／高檔交叉要求當日或前日 K、D 同時低於 20／高於 80；恰好 20 或 80 不屬極端區間。買賣提示只標示當日新交叉，並非持續有效的指令。趨勢確認使用有限且大於零的收盤價與兩日 MA20。

這是本網站訂定、尚未回測的觀察規則，不包含背離、支撐壓力、交易成本或部位規劃。門檻與交叉概念參考 [Fidelity 隨機指標說明](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/slow-stochastic)；此網站保留原有遞迴 KD 算法，並額外加入 MA20 條件，不宣稱完整複製該來源的算法或策略。

## 目前實作

TWSE API 回應驗證、欄名映射、日期與單位檢查、缺漏值、KV 快取與排程均已實作，不需行情 Token。正式模式沒有模擬資料 fallback。

傳輸與儲存使用 `schemaVersion: 2`：`/api/market` 提供公司名錄、實際交易日、`coverage` 與 128 個不可變分組網址，前端最多六個並行請求。每個分組包含 `generation`、`index`、`stocks: [{symbol, history}]`，歷史每列為 `[date, open, high, low, close, volume, foreignBuy, foreignSell, trustBuy, trustSell, dealerBuy, dealerSell]`；法人缺漏為 `null`，前端展開成上列統一格式，均線／KD 計算不變。前端檢查分組版本與公司涵蓋率，拒絕混版或缺組資料。

前端不再逐組下載歷史分組：API 模式只讀取名錄（`/api/v1/market`）與同一版本的市場摘要（`/api/v1/market/summary`），版本、交易日或公司數不一致即拒絕；個股歷史與完整分析改由 `/api/v1/stocks/{symbol}/analysis` 按需取得。分組網址仍公開提供，`combineChunks()` 為其格式的參考解碼器（測試使用）。

載入中的個股清單可搜尋、排序及收藏，尚未取得的股票不以空歷史冒充來源缺漏。每檔指標只在歷史、資料日或設定變更時重算，表格保留未變動的資料列。產業統計在所有分組成功後才顯示；失敗時保留已驗證的個股清單，清楚標示未完成並提供手動重新載入。自選偏好以完整名錄檢查，不會因某個分組尚未取得而被移除。

排程先寫新版本的全部分組，等 KV 傳播後再切換索引。舊版本仍保留供載入中的使用者使用；開始下一代時刪除更舊版本。API 全部只讀快取，瀏覽次數不增加對 TWSE 的請求。`/api/stocks/代碼` 保留單檔展開格式作查核用途，前端不再逐股下載。
## 走勢圖區間與產業選項排序

- **個股**視窗的走勢圖可切換「1 月／3 月／1 年」（30／60／260 個交易日）。**ETF** 不提供區間切換，固定顯示近一年的月線圖（見下方「ETF 基金資料」）。資料來自既有的每檔 260 個交易日歷史（`HISTORY_LIMIT`），**不新增任何儲存**：正式模式由 `/api/v1/stocks/{symbol}/analysis?days=` 多回傳幾個交易日，示範模式由瀏覽器的資料集計算。歷史不足時回傳現有的全部，標題顯示實際交易日數（例如「100 個交易日走勢圖」）。
- 走勢圖下方的三大法人交易量固定為三欄（名稱在上、張數在下），數字再長也不換行，拖曳圖表時整塊高度不變。
- 超過 60 個交易日時只保留選定日的圓點，成交量柱依交易日數變窄；長按拖曳與鍵盤讀值照常。超過一年需調高 `HISTORY_LIMIT`，KV 與 D1 的歷史分片會等比例變大，目前不提供。
- 市場觀察清單的產業選項（第一排大類與第二排細產業）依**選定市場日的成交金額**由高到低排列：成交金額＝該產業各檔「成交股數 × 收盤價」加總，缺價或缺量的個股不計入。沒有任何成交資料的產業排在最後並依名稱排序；「全部」固定在最前面。只影響選項順序，不影響篩選結果與法人排行。

## ETF 資料範圍補充

### ETF 基金資料

個股視窗點開 ETF 時不做進場研究。ETF 持有人最在意配息，所以視窗順序為：配息卡（配息方式、最後買進日、除息日、領息日、每單位配息、近一年殖利率）→ 近一年月線圖（含除息／發息標記）→ 所選月份的配息與成分股 → 配息紀錄 → 基金資料（追蹤指數、類型、發行公司、上市日、規模、受益人數、折溢價） → 預設收合的「技術面與法人」（趨勢、量價、KD、季線、區間表現、三大法人淨買賣）。

基金資料來自 `/api/v1/stocks/{symbol}/fund`，由每日同步寫入 D1（`cloudflare/etf-info/`，migration `0011_etf_info.sql`、`0012_etf_products.sql`、`0013_etf_holdings.sql`）。各來源獨立，任一失敗只保留該來源上一份資料，不影響其他來源與進場研究。為了不佔用 D1 每日寫入額度，每個來源只寫入內容有變動的列，內容相同時不寫入（`UpdatedAt` 因此是該列最後一次變動的時間，不是最後一次同步的時間）：

| 內容 | 來源 | 說明 |
| --- | --- | --- |
| 追蹤指數、基金類型、成立與上市日、發行單位數 | TWSE OpenAPI `t187ap47_L` | 每日比對，更新有變動的基金、移除已不在名單上的；不保存經理人等個人資料 |
| 配息（除息日、基準日、發放日、每單位金額） | TWSE `ETF/etfDiv` | 保留約 400 天內與已公告的未來除息，更舊的自動刪除；更正的公告會更新、撤回的會移除；金額未公告時為 `null` |
| 發行公司、基金規模、受益人數 | TWSE ETF e添富 `ETFortune/ajaxProductsResult`（規模與人數源自集保） | 每日比對，只更新有變動的列 |
| 每月前十大持股與占淨資產比重 | 投信投顧公會「基金持股明細（月）」`sitca.org.tw/ROC/Industry/IN2629.aspx` | **每月**更新；ASP.NET 表單，先讀表單狀態與可查月份，只有尚未儲存的月份才逐一查詢 ETF 類別（AH 指數股票型、AL 主動式）；每個月份整月取代，保留最近 13 個月（約 2.4 萬列），更舊的自動刪除 |
| 預估淨值、折溢價、發行單位數 | TWSE 基本市況 `mis.twse.com.tw/stock/data/all_etf.txt` | 非 OpenAPI 目錄內的檔案，每次讀取都驗證格式；只採用日期等於當日市場日的列，每檔只留最新一筆 |

計算規則（`shared/etf-info.js`）：

- **最後買進日**＝除息日前一個平日。未來的休市日無法事先得知，除息日前一天若休市，實際日期會更早，畫面註明「遇休市會再提前，以投信公告為準」。
- **配息方式**由各除息日（含已公告的未來除息）間隔的中位數判斷：≤45 天月配、≤75 天雙月配、≤135 天季配、≤270 天半年配、≤550 天年配。只有一個除息日時無法判斷，不猜測，改顯示「近一年配息 N 次」。
- 配息卡優先顯示**已公告的下次配息**；沒有公告時顯示最近一次已除息的配息，並標明「已除息，下次尚未公告」。
- 近一年殖利率＝除息日落在（市場日前一年, 市場日］且金額已知的配息合計 ÷ 最新未還原收盤價。區間內沒有配息時為 `null`，不顯示成 0%。
- 折溢價＝市價 ÷ 預估淨值 − 1，由兩個公布數字重新計算。淨值是收盤後的**預估值**，畫面標示「預估淨值」。
- 規模優先採 TWSE 公布的基金規模（`sizeBasis: "reported"`）；沒有時才用發行單位數 × 預估淨值，並標示「規模（估算）」。
- 區間表現（近 5／20 日、距 30 日收盤高低點）由 30 日走勢圖的未還原收盤價計算；缺價的一端不計算。
- 沒有資料的欄位留白或整塊不顯示，不以 0 代替。
- **月線圖**：把近一年的日線（最多 260 個交易日）依月份合併，每月一點：收盤價取當月最後一個有價的交易日、成交量為當月加總、漲跌幅與上一個有收盤價的月份比較（第一個月沒有比較對象，留白）。整月都沒有收盤價時該點留白，不補值。不畫均線，也不顯示三大法人交易量。ETF 歷史自加入日起累積，月份數可能少於 13。
- **除息／發息標記**：月線圖下方兩列，除息日與發放日各自標在所屬月份的位置，與圖上的點對齊；落在圖表月份之外的日期（例如已公告的未來除息）不標，改由配息卡呈現。
- **所選月份面板**：點選、拖曳或用方向鍵在月線圖上選一個月，圖下方顯示該月的除息／發息日與金額，以及該月的前十大成分股；預設為最新月份。月報在月底後數週才公布：所選月份沒有自己的月報時，顯示最接近的較早月報並標明「這個月的月報尚未公布，顯示 X 月的持股」，不會把別月的持股當成該月。標的種類為「國內上市」且代號為四碼的持股可點開該檔個股視窗，其餘只顯示文字。
- 公會報表以**基金名稱**列示、沒有股票代號，由 `cloudflare/etf-info/holdings.js` 把名稱化簡後與 TWSE 基金基本資料的中文名稱比對（去除括號內的警語、「證券投資信託」「基金」「ETF」等字樣，傘型基金取子基金名稱）。比對不到、或兩檔不同基金化簡後同名時**不採用**，寧可不顯示也不顯示成別檔基金的持股；同一基金的不同受益憑證（如 00636 與 00636K）共用同一份持股。實測約七成 ETF 可對應，新上市、期貨型與槓桿反向型通常沒有。
- 沒有持股資料的 ETF 只顯示說明文字；視窗不提供任何導向外部網站的連結。每日持股與持股異動需逐家投信另外串接，尚未提供；經理費沒有全市場來源。

正式名錄可包含 `assetType: "etf"`、`sector: "ETF"`、`currency: "TWD"` 的上市 ETF；一般公司維持既有格式。代碼支援 4–6 位數字及 5 位數字加一個大寫英文字母。分組請共用 `src/market-codec.js` 的 `shardOf()`，不可直接將字母代碼轉成 Number。公司數字代碼的既有分組不變。

市場頁的 ETF 分頁只列 ETF（不套用產業選項），市場觀察清單與其產業選項排除 ETF；自選與搜尋可包含 ETF；產業法人排行、區間加總、家數、TOP1 與產業明細一律排除 ETF。首次 ETF 只提供最新一日，後續逐日累積；缺少所需歷史或官方資料時保留 null／資料不足，不補零、不以個股歷史替代。
