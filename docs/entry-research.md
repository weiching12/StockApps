# 進場研究模型（目前上線：entry-research-v3）

> **v3（2026-11-03 起）**：沿用 v2 的初步門檻、準備度與價格計畫，只把訊號有效期由 3 個交易日改為 **1 天**：訊號只在觸發當天晚上產生明日進場候選，下一個交易日起為「訊號已過期」，需等待新的觸發。依據見 [entry-research-signal-study.md](entry-research-signal-study.md)：2026-10-01～11-03 歷史中，訊號第 1 天的候選持有 5 日平均 +0.68%（勝率 51%），第 2、3 天分別為 −0.73%、−1.17%。效期只有 1 天，有效期間內出現否決條件的情況不會發生。研究樣本自 v3 起以 `entry-research-v3` 累積。

> **v2（2026-11-03 起）**：第一階段改為五項否決條件的「初步門檻」，規格與參數依據見 [entry-research-gates-v2.md](entry-research-gates-v2.md)，v1／v2 歷史比較見 [entry-research-v2-comparison.md](entry-research-v2-comparison.md)。準備度的構面強度改為 V1.2 趨勢與法人兩分項平均，權重 50／30／20 不變；第二、三階段（訊號、價格計畫）與樣本保存、回測流程不變。研究樣本自 v2 起累積（模型版本 `entry-research-v2`）。下文第一階段與準備度的「五大核心門檻」「五構面平均」為 v1 內容，保留作為對照。
>
> 畫面：市場清單顯示「初步門檻通過」或第一個觸發的否決條件（例如「近期放量下跌 等 2 項」）。個股視窗的初步門檻為五個並排圖示，點選圖示顯示計算方式與實際數據，參考依據預設收合、點開才顯示；走勢圖下方先顯示「明日進場評估」作為快速解讀（成立原因預設收合），之後依判定順序排列：初步門檻 → 進場訊號分析 → 進場準備度 → 明日價格計畫；未通過的股票自動展開第一個觸發項，且不顯示準備度、訊號與價格計畫。走勢圖維持在股票名稱下方的原始位置，手機半開時顯示名稱與走勢圖。走勢圖的進場參考、價格上限、失效價與訊號日一律為灰色線，以虛線樣式區分，並在圖內直接標示「進場／上限／失效」與價格，避免與收盤價、月線、季線的顏色混淆。「進場訊號分析」先說明判定方式（形成條件、觸發條件、訊號有效 3 個交易日、過期與失效），再列出兩種型態的全部條件與實際數值、逐項標示 ✓／✗：已觸發過的型態依訊號日收盤判定，另一種依當日收盤判定；已觸發或已形成的型態預設展開。研究結果的 `entryResearch.setups` 提供當日兩種型態的判定，每項條件含 `stage`（setup／trigger）與 `detail`（實際數值）。收盤價、漲跌與資料日期只在標題與走勢圖顯示一次；價格資料提醒（例如未還原價格）只在走勢圖下方顯示一次，不再重複列入明日評估的主要風險。研究樣本表沿用五個門檻欄位，依模型版本對應各自的門檻。

`shared/entry-research.js` 的 `evaluateEntryResearch()` 是唯一入口，參數集中在 `shared/entry-research-model.js`。前後端與歷史回測都呼叫同一份程式，前端不自行計算。**所有新參數都是暫定值，尚未經過歷史回測驗證。**

評估某個交易日時，只讀取該日（含）以前的 K 線；`tests/entry-research.test.js` 會比對「提供完整未來資料」與「只提供當日以前資料」的結果必須完全相同。

## 第一階段：五大核心門檻（沿用 V1.2，未改門檻）

直接使用 `evaluateCoreConditions()`，條件見 [entry-score.md](entry-score.md)：

| 構面 | PASS 條件 |
| --- | --- |
| 趨勢結構 | 收盤 > MA20 > MA60，且 MA20、MA60 皆較前一交易日上升 |
| KD 動能 | K > D，且 K 未連續兩日下降 |
| 量價表現 | 未出現跌幅超過 0.50% 且 RVOL20 ≥ 2 |
| 法人籌碼 | 近五日三大法人合計淨額 ≥ 0 |
| 基礎價格風險 | MA20 乖離 ≤ 10%，且前十日最低價 < 收盤 |

門檻總結果：

- **PASS**：五項皆 PASS，且沒有前提資料缺漏（61 個完整交易日、60 日內公司行動已查核）。
- **FAIL**：任一項 FAIL。其他項目再好也不能抵銷。
- **UNKNOWN**：沒有 FAIL，但有 UNKNOWN 或前提資料缺漏。UNKNOWN 永遠不當 PASS。

只有 PASS 進入第二階段；FAIL 的研究狀態為 `NOT_ELIGIBLE`，UNKNOWN 為 `DATA_INSUFFICIENT`，兩者的進場準備度皆為 `null`。

價格基準沿用 V1.2：60 日內有除息且已查核時，使用除息參考價調整後的歷史（`researchPriceHistory()`），門檻、訊號與價格計畫用同一份價格。

## 第二階段：進場訊號（本次新增，暫定參數）

### 順勢回踩恢復 `PULLBACK_RECOVERY`

在交易日 t 觸發，需全部成立：

1. t 之前 5 個交易日內，任一日最低價 ≤ 當日 MA20 + 0.5 × ATR14（回踩）。
2. 這 5 個交易日收盤皆 ≥ 當日 MA60（未破壞結構）。
3. t 日收盤 > MA20。
4. t 日收盤 > 前一交易日最高價。
5. t 日 K 值 > 前一交易日 K 值。

- 進場參考價：t 日收盤。
- 失效價：回踩期間（含 t 日）最低價 − 0.25 × ATR14。
- KD 確認：K > D 且 K 上升；量能確認：RVOL20 ≥ 1（不足時列入風險提示，不阻擋觸發）。

### 整理區間向上突破 `RANGE_BREAKOUT`

1. t 之前 20 個交易日（不含 t）的最高價與最低價構成整理區間，振幅 ≤ 4 × ATR14。
2. t 日收盤 > 區間上緣，且前一日收盤 ≤ 區間上緣（首次突破）。
3. t 日 RVOL20 ≥ 1.5。
4. t 日 K > D。

- 進場參考價：區間上緣。
- 失效價：max(區間上緣 − 1 × ATR14, 區間下緣)。
- RVOL20 ≥ 2 視為量能強確認；收盤高於區間上緣超過 3% 時提示追價風險。

ATR14 一律以 t 日為終點的 61 個交易日計算，與 V1.2 相同。

### 研究狀態

從評估日往回最多 10 個交易日，找最近一次觸發（同日兩種都觸發時取訊號品質較高者）：

| 狀態 | 條件 |
| --- | --- |
| `TRIGGERED` | 觸發日起 3 個交易日內（觸發日＋其後 2 日），且其後收盤未跌破失效價 |
| `SIGNAL_INVALIDATED` | 觸發後任一日收盤低於失效價 |
| `SIGNAL_EXPIRED` | 超過 3 個交易日且未失效 |
| `WAIT_TRIGGER` | 10 個交易日內沒有觸發 |
| `DATA_INSUFFICIENT` | 門檻 UNKNOWN 或評估日 ATR14 無法計算 |
| `NOT_ELIGIBLE` | 門檻 FAIL（本次新增的代碼，前端顯示「未通過五大門檻」） |

## 第二階段：進場準備度 `entryReadinessScore`（本次新增，暫定權重）

僅門檻 PASS 時計算，0～100 分，**不是 V1.2 的株研評分、不是獲利機率、也不是買進指令**。

| 分項 | 權重 | 計算 |
| --- | --- | --- |
| 五大構面強度 | 50% | V1.2 五個構面分數的**簡單平均**（不是 V1.2 的加權最終分數） |
| 進場訊號品質 | 30% | 已觸發：60 ＋ KD 確認 15 ＋ 量能確認 15（突破只達 1.5 倍給 5）＋ 新鮮度（當日 10、隔日 5）；已過期 20；已失效 0；等待中：正在形成的型態 30 ＋ K 上升 10 ＋ 只差一項條件 10，上限 50 |
| 進場位置與時機 | 20% | MA20 乖離 ≤ 3% 為 100、≤ 6% 為 70、≤ 10% 為 30；已觸發時再與「收盤距進場參考價的 ATR 倍數」取較低者（≤ 0.25 為 100、≤ 0.5 為 70、≤ 1 為 30、其餘 0） |

等待中的訊號品質上限為 50、已觸發至少 60，所以分數高的股票若尚未觸發，狀態仍是「等待進場訊號」，不會變成明日候選。結果保留三個分項分數、表現較好與較弱的構面、已成立與尚未成立的條件、風險提示。

## ETF 不評估

ETF 追蹤指數或一籃子標的，不適用以個股設計的進場時機判斷（法人籌碼、產業、回踩與突破型態）。`entryResearchApplies()` 對 ETF 回傳 false：摘要 API 與個股分析 API 的 `entryResearch` 為 `null`，清單顯示「ETF 不評估」，個股視窗說明不判斷進場時機；每日研究樣本不記錄 ETF。2026-11-10 之前已存的 ETF 樣本保留在資料庫，但樣本與回測查詢一律以代號 `00` 開頭排除（臺灣證券交易所 ETF 代號皆以 00 開頭）。

## 第三階段：明日進場評估（本次新增，暫定參數）

只有 `TRIGGERED` 會產生價格：

| 欄位 | 計算 |
| --- | --- |
| `referenceClose` | 評估日收盤 |
| `entryReferencePrice` | 訊號的進場參考價 |
| `entryPriceLower` | `null`，第一版策略未定義下限 |
| `entryPriceUpper` | 進場參考價 ＋ 0.5 × ATR14 |
| `invalidationPrice` | 訊號的失效價 |
| `riskPercent` | (進場參考價 − 失效價) ÷ 進場參考價 |
| `maxRiskPercent` | (上限 − 失效價) ÷ 上限 |
| `planExpiresAt` | 下一個交易日；行事曆尚未出現時為 `null`，並以 `planExpiresAfterSessions: 1` 表示 |

狀態：

- `NEXT_DAY_CANDIDATE`：收盤未超過上限，且 `maxRiskPercent` ≤ 8%。
- `PRICE_TOO_HIGH`：收盤已高於上限，或以上限進場的風險超過 8%。
- `PLAN_INVALIDATED`：訊號已失效。
- `WAIT_TRIGGER`：尚未觸發或訊號已過期。
- `DATA_INSUFFICIENT`：門檻 UNKNOWN，或 ATR14／失效價無法建立（此時所有價格為 `null`，不輸出看似精確的價格）。
- `NOT_ELIGIBLE`：門檻 FAIL，前端顯示「尚未評估」。

沒有即時行情，候選一律 `requiresPriceConfirmation: true`。`checkNextDayPlan(plan, nextBar)` 只用下一交易日的**開盤價**判斷：高於上限 `OPEN_ABOVE_UPPER`（不追價）、不高於失效價 `OPEN_BELOW_INVALIDATION`（取消）、其餘 `WITHIN_PLAN`（以開盤價模擬成交）；還沒有隔日行情為 `AWAITING_PRICE`。原計畫的上限與失效價不會因為市場價格而調整。

## 每日樣本保存（批次 B）

### 資料表（migration `0010_entry_research.sql`，只新增）

- `entry_research_samples`：主鍵 `(Symbol, TradeDate, ModelVersion)`，**全市場每一檔**（含未通過門檻者）每日一列。五個門檻結果、通過數、準備度與三個分項、研究狀態、策略類型、訊號日、明日評估、參考價、上限、失效價、風險、ATR14、資料品質、價格基準、來源（`daily`／`historical-recalculation`）與發布版本各自成欄並建立索引；完整說明（門檻原因與數值、訊號依據、價格計畫、警示）存在 `DetailJson`。寫入一律 `INSERT OR IGNORE`：同一股票、日期、模型版本只保留第一次的結果，不會被後來的資料覆蓋。要重算必須升模型版本。
- `entry_research_outcomes`：同主鍵，後續表現與模擬交易，與樣本分開存放，樣本列永遠不變。
- `entry_research_runs`：每次擷取的紀錄（交易日、模型、發布版本、樣本數、新增、略過、後續表現更新數、狀態、錯誤）。同一交易日若之後出現修正版發布，會新增一筆紀錄，但不改寫已存在的樣本。

### 盤後流程

`worker.js` 的排程在同步完成（`phase === "done"`）後執行**進場研究擷取**（`entry-research-capture.js`，在同步協調器的佇列內執行），失敗會記錄原因並在下一次排程重試。原本的每日 V1.2 研究快照已停止寫入（舊資料仍保留在 D1，`/api/v1/favorites/research` 只讀取既有快照）。

1. 同一發布版本已完成就立即返回（排程每分鐘觸發，不會重複讀取全市場）。
2. 以與 V1.2 相同的已分析行情與公司行動資料，對每一檔執行 `evaluateEntryResearch()` 並寫入樣本。
3. 更新最近 35 個交易日內、後續表現仍為 `PENDING` 的樣本；只寫入結果有變化的列。樣本日後 30 個交易日仍無法完成者標記為 `UNAVAILABLE`。
4. 記錄執行結果。

### 後續表現（`shared/entry-research-outcome.js`）

- 1／5／10／20 日報酬：以樣本日收盤為基準，比較第 N 個市場交易日收盤。
- MFE／MAE：其後 20 個交易日的最高價、最低價相對樣本日收盤。
- 是否觸及失效價（最低價 ≤ 失效價）、是否達到目標價（進場參考價 ＋ 2 × 風險距離，暫定）；同一天兩者都觸及時標記無法判斷先後。
- 模擬交易：只對 `NEXT_DAY_CANDIDATE`，以下一交易日開盤價依 `checkNextDayPlan()` 判斷成交；成交後持有 5／10／20 日，或收盤跌破失效價時於隔日開盤出場。報酬扣除手續費雙邊 0.1425%、證交稅 0.3%、滑價雙邊各 0.1%。
- 未完成的期間為 `PENDING`，值為 `null`，不填 0；期間有除權息（未還原價格無法比較）、停牌或缺行情為 `UNAVAILABLE`；公司行動尚未查核時維持 `PENDING`。

### 查詢 API

`GET /api/v1/research/samples`：參數 `model`、`from`、`to`、`symbol`、`gate`、`status`、`setup`、`nextDay`、`source`、`minScore`、`maxScore`、`limit`（≤ 200）、`offset`、`detail=1`（附完整說明）。依日期新到舊、同日依準備度排序。

`GET /api/v1/research/backtest`：與樣本 API 相同的篩選參數（不含分頁與 `detail`），另加 `horizon`（5／10／20，預設 10）。全部以 D1 SQL 彙總，回傳：

- `totals`：樣本數、交易日數與起訖日、門檻通過、訊號觸發、明日候選、模擬成交、尚未滿持有期的成交筆數。
- `trades`：持有期模擬交易淨報酬的筆數、勝率（淨報酬 > 0）、平均報酬、平均獲利、平均虧損、最大回撤。
- `forward`：樣本日收盤後 N 日報酬（含未通過門檻的樣本）與 20 日平均 MFE／MAE。
- `readinessBuckets`（0–39、40–59、60–69、70–79、80–89、90–100）、`setups`（回踩恢復／區間突破）、`horizons`（5／10／20 日）各自的交易與收盤後報酬。
- `equity`：資金分成持有天數（N）等份，每個樣本日投入一份、平均分配給當日成交的候選，依日期累積的報酬與距前高回撤。若把重疊持有期間的報酬直接逐日連乘，漲跌會被放大約 N 倍。
- `daily`：每日樣本、門檻通過與明日候選數；`distribution`：淨報酬每 2% 一組（±20% 以外合併）。
- 少於 30 筆（`meta.minimumSamples`）的分組標示 `insufficient`；沒有資料的平均值為 `null`，不補 0。

### 容量

workerd／D1 實測：每筆樣本說明約 1.4 KB，加上欄位與索引約 2 KB；全市場約 1,340 檔，每日約 2.5～3 MB。

**保留期限（暫定）：半年。** 每次擷取完成後，刪除交易日早於「評估日往前 6 個月」的樣本、後續表現與執行紀錄（`retentionCutoff()`，月底日期取當月最後一天）。穩定狀態約 125 個交易日，樣本約 330～380 MB。回測只能涵蓋最近半年；已刪除的資料無法復原。

## 前端呈現（批次 C）

- 市場摘要 API 每檔附 `entryResearch` 精簡欄位（門檻結果與通過數、準備度、研究狀態、策略、訊號日、明日評估、資料品質）；個股分析 API 附完整結果。示範模式在瀏覽器以同一個共用模組計算，前端不另寫規則。摘要快取版本已更新。
- 市場觀察清單：以「進場準備度」（分數與門檻 x/5，UNKNOWN 顯示「待確認」）及「進場研究」（研究狀態；訊號已觸發時，標籤不再只寫「進場訊號已觸發」，而是直接寫下一交易日結果：「明日可進場」「訊號觸發・不進場」「訊號觸發・資料不足」；寬螢幕的第二行再以短字顯示「超出容許範圍／資料不足」與型態「回踩恢復／區間突破」，滑鼠停留可看完整文字；其他狀態只顯示研究狀態）兩欄取代原「株研評分」欄。預設排序：明日進場候選 → 其他門檻通過 → 價格超出容許範圍 → 未通過或資料不足，組內依準備度由高至低；另有「進場研究」篩選（明日進場候選、價格超出容許範圍、等待進場訊號、未通過初步門檻，各階段互不重疊；準備度高低改用排序）與排序選單（準備度、漲跌幅、成交量、代碼）。手機版改為卡片，不需橫向捲動；工具列為一排可左右滑動的條件（全部、自選、進場研究條件、季線與 K 值）與排序；產業以面板上方的產業選項切換，搜尋為側欄的獨立頁面。範圍條件與研究條件可同時套用，再點一次取消，「全部」一併清除；研究條件與桌面版的選單是同一個篩選。
- 個股視窗：基本資訊與資料品質 → 明日進場評估 → 進場準備度與分項 → 五大核心門檻（狀態、原因、門檻條件與數據）→ 進場訊號分析 → 風險與計算方式 → 30 日走勢圖（標示進場參考、價格上限、失效價與訊號日），其下為三大法人交易量線（口徑見 `docs/data-contract.md`）。舊版株研評分 V1.2 區塊已移除；V1.2 只作為進場研究的計算輸入，不再單獨顯示。
- 明日進場評估卡的「技術型態」欄（原「進場策略」）顯示評估日偵測到的型態（順勢回踩恢復／整理區間向上突破），只代表訊號來源，不表示可以進場；型態只用價格、均線、KD、ATR 與成交量判定。
- 明日進場評估卡先回答「下一交易日能不能進場」：標題為「11/10 可進場／不進場」（行事曆尚無下一交易日時寫「下一交易日」），下方註明「依 11/09 收盤、以固定研究規則判讀，非買賣指令」。
  - 可進場（`NEXT_DAY_CANDIDATE`）：並列參考買入價、最高價（開盤上限）、最低價（停損價），並說明只看下一交易日開盤價是否高於停損價且不高於最高價。
  - 不進場：只寫一句原因，不再列出看似可用的價格。`PRICE_TOO_HIGH` 會區分「收盤已高於最高價，不追價」與「停損距離太遠」；後者以使用者看得到的收盤價說明：「以 11/09 收盤價 x 買進、跌到停損價 y 會虧損 z%，超過單筆上限 8%」，收盤價本身未超過 8% 時再補上「但開盤若在上限買進會虧損 w%」。
- 「風險與計算方式」取代原「明日價格計畫」：先並列「以收盤價買進」與「以開盤上限買進」的停損虧損、「單筆虧損上限（標準）8%」及符合／超過上限（判定以開盤上限的最壞情況為準），再以實際數字列出參考買入價、最高價、停損價、停損虧損的算式、8% 的意義（研究模型暫定參數，尚未經回測驗證）與 ATR14；超過上限時另列「買入價需 ≤ x 才符合 8%」，並註明規則不會等待回落後再買。
- 進場準備度的「構面強度計算方式」可展開：構面強度 =（趨勢結構分數 ＋ 法人籌碼分數）÷ 2；趨勢結構 = 四項均線條件（收盤高於月線、月線高於季線、月線上升、季線上升）× 20 ＋ 近五日收盤站上月線天數 × 4；法人籌碼 = 占比分數（50 ＋ 50 × 近五日法人淨額占成交量 ÷ 5%，限 0～100）× 60% ＋ 合計買超天數 × 5 ＋ 累計買超法人類別數 × 5。「查看產業法人」連結移到此處。手機半開狀態顯示基本資訊與明日評估卡片。

## 策略回測頁（批次 D）

導覽有「策略回測」，登入帳號才看得到；未登入時入口隱藏，研究樣本與回測 API 回應 401（尚未更改初始密碼的帳號同樣不可使用）。篩選列（起訖日、策略、五大門檻、明日狀態、準備度下限、股票代號、持有 5／10／20 日）改變後重新查詢回測與樣本 API，所有數字由後端彙總，前端不重算規則。頁面依序顯示統計範圍說明、樣本概況、模擬交易結果、累積報酬與回撤曲線（附資料表）、準備度分組、策略比較、持有天數比較、報酬分布與每日樣本分布，最後是可分頁的研究樣本清單；點選樣本開啟當日保存的說明與後續表現。樣本不足時明確標示；沒有樣本時顯示空狀態，示範模式不產生模擬回測結果。頁面註明樣本只保留 6 個月。
